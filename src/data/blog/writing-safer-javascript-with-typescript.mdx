## What is TypeScript?

TypeScript is just types with JavaScript.

JS is loosely typed language, TypeScript allows specifying the types of data being passed around within the code.

TypeScript is a superset of JavaScript.

TypeScript code is compiled into JavaScript because browsers can only execute JavaScript.

TS is type checker, because of type checker we get consistency in code.

**TypeScript** = **JavaScript** + **static typing**

Example:

```tsx
let age: number = 10; // The age variable will always hold number.
// age is a variable name
// : number is a type annotation

// Later if you wanna change it to some other type then:
age = "Luffy"; // This gives an error
```

## Basic Types

Types describe nature of data.

### **Primitive Types**

```tsx
let isAdmin: boolean = true; //boolean -> true / false

let name: string = "Luffy"; // String -> Collection of characters

let score: number = 98; // number -> interger or decimal number

let emptyValue: null = null; // null -> intentional absence of value

let notAssigned: undefined = undefined; // undefined -> variable declared but not assigned

const id = Symbol(); // Symbol -> unique value

const user = {
  name: "Luffy",
  [id]: 101,
};

console.log(user[id]); // Output: 101
```

**Annotation:** We have to give a data type in lower case to tell what kind of values will be store inside it. Example:- `:number`

Always use `const` or `let` to declare or initialize the variables .

## Arrays

Arrays are a ordered collection of elements. In TS you can declare the type of array:-

```tsx
let skills: string[] = [
  "Web Development",
  "UI/UX Designer",
  "Backend Developement",
];
// string[] ->  Array contains only strings

let marks: number[] = [70, 80, 90];
// number[] -> marks contains only numbers

// If you try:
skills.push(100); // Error: Number not allowed

// Other ways of declaring Arrays are:
const rating: Array<number> = [4.5, 3.5, 2.6];

// Multi-Dimensional Array
const table: number[][] = [
  // 2D Array
  [1, 2, 3],
  [4, 5, 6],
];

// Tuple in TypeScript
// A tuple allows us to define an array with a fixed number of elements
// where each position has a specific type.
const shoeType: [string, number] = ["Bata", "8"];
const carType: [brand: string, modelNo: number] = ["BMW", "5"];
```

Type Safety in action.

## Type Inference

Relax - You don’t need to type everything.

TypeScript is smart.

```tsx
let name = "Nami"; // TypeScript automatically infers -> string

const age = 17; // Automcatically infers -> number

const cars = ["BMW", "Mustang", "Audi"]; // infers into -> string[]
```

This is called Type Inference. It reduces typing effort and keeps code clean.

For simple variable use type inference.

## Enums

Enum is a special type with represents a group of constants (unchangeable variables).

Enums let you define a fixed set of named values.

```tsx
enum Directions {
  North,
  East,
  South,
  West,
}

let currentDirection = Directions.North;
console.log(currentDirection); // logs 0 because North is the first value

enum status {
  pending = 100,
  cancelled, // 101
  success, // 102
} // the number automatically increases when give to one

console.log(status.success); // logs 102

enum ChaiType {
  masala = "masala",
  ginger = "ginger",
}

console.log(ChaiType.ginger); // logs ginger
```

In enums, technically, you can mix and match string and numeric enum values, but it is recommended not to do so.

## Optional & Default Properties

Real-world data’s are messy. Sometimes fields are optional.

Optional properties allow certain fields to be included or omitted when creating an object.

```tsx
type User = {
  name: string;
  age?: number;
  // ? -> optinal property
};

function add(a: number, b: number, c?: number): void {
  console.log(a + b + c);
}

add(5, 3); // it is optinal to pass the 3rd variable

// Same way we can do it in objects, types and interfaces too

const person: User = {
  name: "Luffy",
};

const person1: User = {
  name: "Zoro",
  age: 19,
};

// We even readonly keyword used for variables not to be modified & just to be read
type Car = {
  modelName: string;
  readonly modelYear: number;
};

const Car1: Car = {
  modelName: "BMW",
  modelYear: 1986, // throws error cause we cannot modify readonly values
};
```

Readonly properties can be accessed, but they cannot be reassigned or modified after initialization.

## Union Types

Union Types are used when a value can be more than a single type.

Such as when a property would be `string` or `number` .

Union = OR

```tsx
const getMonth = (month: string | number) => {
  console.log(month);
};

getMonth(12); // takes number as input & logs 12
getMonth("December"); // takes string as input & logs December

function printStatusCode(code: string | number) {
  console.log(`My status code is ${code.toUpperCase()}.`); // error: Property 'toUpperCase' does not exist on type 'string | number'. Property 'toUpperCase' does not exist on type 'number'
}
```

Very common in APIs where IDs might be numeric or string-based.

## Interface vs Types

Beginners mostly confuse between interfaces and types at beginning.

In simple words:

> They define what an object looks like.

So first let’s understand what interface and Types is:

### Interface

Interfaces are similar to types, except that they only apply to `object` types.

```tsx
interface User {
  name: string; // must be string
  age: number; // must be number
}

const user1: User = {
  name: "Luffy",
  age: 21,
};

// If you forget a property:
const user2: User = {
  name: "Zoro",
  // ❌ Error: age is missing
};

// We can use extends to inherit properties from a interface to another one.
interface Person {
  name: string;
  age: number;
}

interface Employee extends Person {
  employeeId: number;
  department: string;
}
```

The interface enforces structure.

---

### Type

A `type` can also define object shapes.

```tsx
type User = {
  name: string;
  age: number;
};

const user: User = {
  name: "Rahul",
  age: 22,
};

// So far, looks the same as interface.

// We can't use extends keyword but we use intersection &
type Person = {
  name: string;
  age: number;
};

type Employee = Person & {
  employeeId: number;
  department: string;
};
// & means combine both types.
```

Using Interface and types are almost same. They both apply on object’s.

Except that `type` can be used for creating unions, creating intersections and defining complex types.

And `interface` can be used while working with classes, building large application's, designing API’s.

## Generics in TypeScript

### What are generics

Generics allow you to write reusable, flexible types.

Instead of locking a function or type to one specific data type, generic allows it to adapt.

Think of it like: “A Placeholder for a type.”

We usually use `T` (but it can be any name).

---

### Basic Generic Function

```tsx
// Without generics:
function identity(value: string): string {
  return value;
}
// Only used for strings.

// With generics:
function identity<T>(value: T): T {
  // T = placeholder type
  return value;
}

// now it works for anything.
identity<string>("Hello");
identity<number>(123);
identity<boolean>(true);
```

What happens?

- If you pass string → T becomes string.
- If you pass number → T becomes number.

---

### Generic Arrays

```tsx
function getFirstItem<T>(items: T[]): T {
  return items[0];
}

// usage:
getFirstItem<number>([1, 2, 3]);
getFirstItem<string>(["a", "b", "c"]);
```

`T[]` means: An array of type `T` .

---

### Generic with constraints (`extends`)

Sometimes you don’t want “anything”. You want “anything with some structure”.

```tsx
function printLength<T extends { length: number }>(item: T): void {
  console.log(item.length);
}

// Now T must have a length property.
// Valid:
printLength("Hello"); // string has length
printLength([1, 2, 3]); // array has length

// Invalid:
printLength(123);
// ❌ number does not have length
```

This is called generic constraint.

## Utility Types (Built-in Generics)

Now we move to the powerful built-in helpers.

These are generic types provided by TypeScript.

---

### `Partial<T>`

Makes all properties optional.

```tsx
type User = {
  id: number;
  name: string;
  email: string;
};

type UpdateUser = Partial<User>;

// Equivalent to:
type UpdateUser = {
  id?: number;
  name?: string;
  email?: string;
};

// Why useful?
// When updating data:
const updateData: UpdateUser = {
  name: "New Name",
};
```

You don't need to send full object.

---

### `Required<T>`

Opposite of Partial.

Makes al properties required.

```tsx
type OptionalUser = {
  id?: number;
  name?: string;
};

type StrictUser = Required<OptionalUser>;
// Now both properties are mandatory.
```

---

### `Readonly<T>`

Makes properties immutable.

```tsx
type User = {
  id: number;
  name: string;
};

const user: Readonly<User> = {
  id: 1,
  name: "Mohan",
};

user.name = "Rahul";
// ❌ Error — cannot modify
```

Prevents accidental mutations(changes of data).

---

### `Pick<T, K>`

To select specific properties.

```tsx
type User = {
  id: number;
  name: string;
  email: string;
};

// Pick only 'id' and 'name' from the User type
type UserPreview = Pick<User, "id" | "name">;

// This object is valid because it contains exactly 'id' and 'name'
const preview: UserPreview = {
  id: 1,
  name: "Mohan",
};

// Error: Property 'email' does not exist on type 'UserPreview'
// preview.email = "mohan@example.com";
```

Useful for:

- API responses.
- Lightweight objects

---

### `Omit<T,K>`

Remove certain properties. Opposite of `Pick<T, K>` .

```tsx
type User = {
  id: number;
  name: string;
  password: string;
};

// Creates a new type by removing "password" from User
type PublicUser = Omit<User, "password">;

// This is valid:
const userProfile: PublicUser = {
  id: 101,
  name: "Arjun",
};

// Error: Property 'password' does not exist on type 'PublicUser'
```

Very common in backend + frontend separation.

---

### `Record<T, K>`

Creates an object with keys of specific type.

```tsx
type UserRoles = Record<string, string>;

// Equivalent to:
type UserRoles = {
  [key: string]: string;
};

// Example:
const roles: UserRoles = {
  admin: "Full Access",
  editor: "Edit Access",
};
```

---

### `Promise<T>`

Promise is also generic.

It defines what type will be returned when resolved.

```tsx
function fetchUser(): Promise<User> {
  return fetch("/api/user").then((res) => res.json());
}

// Promise<User> means after async relsoves -> you get a User type.

// Example:
async function loadUser() {
  const user = await fetchUser();
  // user is strongly typed
}
```

If API change structure → TypeScript warns you.

---

### Combining Utility Types

```tsx
type User = {
  id: number;
  name: string;
  email: string;
  password: string;
};

type SafeUserUpdate = Partial<Omit<User, "password">>;
```

What this means:

- Removes password
- Makes remaining field optional

This is production-level typing.

### Typing Component Props

This is 80% of React + TS usage.

```tsx
type ButtonProps = {
  label: string; // text to display
  onClick: () => void; // function prop
  disabled?: boolean; // optional prop
};

const Button = ({ label, onClick, disabled }: ButtonProps) => {
  return (
    <button onClick={onClick} disabled={disabled}>
      {label}
    </button>
  );
};
```

Why this matter?

- Prevent missing props
- Prevents wrong types
- Makes component predictable.

So the bug are stopped instantly instead in production.

---

### Typing Function Props

Functions props are very common.

```tsx
type UserCardProps = {
  onSelect: (id: number) => void;
};

const UserCard = ({ onSelect }: UserCardProps) => {
  return <button onClick={() => onSelect(1)}>Select</button>;
};

// Explaination of the above program
// - Accepts number
// - Returns Nothing
```

---

### Typing useState

**Simple Case(Type inference works)**

```tsx
const [count, setCount] = useState(0);
// inferred as number

// When you must Type it
// - Initial value is null
const [user, setUser] = useState<User | null>(null);
// Without typing, TS thinks it's only null

// - arrays
type User = {
  id: number;
  name: string;
};

const [users, setUsers] = useState<User[]>([]);
// now users is always an array of user.
```

---

### Typing Events (React-Specific)

These types come from React — not plain TypeScript.

```tsx
// Input Change Event
const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  console.log(e.target.value);
};

// Form Event
const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => {
  console.log("Clicked");
};
```

Important: These are React event types, not DOM types.

---

### Typing Children

If your component accepts children;

```tsx
import { ReactNode } from "react";

type CardProps = {
  children: ReactNode;
};

const Card = ({ children }: CardProps) => {
  return <div>{children}</div>;
};
```

`ReactNode` allows:

- string
- JSX
- fragments
- arrays
- null

---

### Extending Native HTML Props

This is a professional pattern. Instead of rewriting all button props:

```tsx
type ButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement> & {
  variant: "primary" | "secondary";
};

const Button = ({ variant, ...rest }: ButtonProps) => {
  return <button {...rest} />;
};
```

Now your component automatically supports:

- `onClick`
- `disabled`
- `type`
- `className`, etc.

Very powerful pattern.

---

### Generics in React

Generics makes components reusable.

```tsx
type ListProps<T> = {
  items: T[];
  renderItem: (item: T) => React.ReactNode;
};

function List<T>({ items, renderItem }: ListProps<T>) {
  return (
    <ul>
      {items.map((item, index) => (
        <li key={index}>{renderItem(item)}</li>
      ))}
    </ul>
  );
}

// Usage:
<List items={[1, 2, 3]} renderItem={(item) => <span>{item}</span>} />;
```

What’s happening here is:

- `T` adapts automatically
- Works for numbers, strings, objects, anything

This is real scalable React architecture.

## Common Beginner Mistakes

When starting with TypeScript, most developers struggle not because it’s hard — but because they approach it the wrong way.

Let’s fix that:

---

### Typing Everything Manually

You don’t need to write types for every single variable.

```tsx
const name: string = "Luffy";
```

This works — but it’s unnecessary.

```tsx
const name = "Mohan";
// TypeScript already knows it's a string
```

Let inference work for you.

---

### **Fighting inference**

Don’t manually type everything. Trust TypeScript unless necessary.

---

### **Ignoring errors**

Red lines protect you. Don’t blindly use `@ts-ignore`.

---

### **Overcomplicating types**

Avoid advanced patterns before mastering basics. Keep it simple.

---

### **Copying complex generics**

If you don’t understand it, don’t use it.

---

**🔴 Red lines are future bug prevention.**

**Practice regularly** — that’s how TypeScript clicks.
